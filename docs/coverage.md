# 行の網羅

kome (`crates/kome/src`) の全ての行について、試験か検証のどれかが確かめていることを CI が確かめる
(ジョブ `cover`、`scripts/ci/cover.sh`)。

## 測り方

1. ワークスペースの全ての試験 (単体の試験、決定的シミュレーション、参照ホスト、記録と再生、文書の中の例)
   を、通った行を数える設定 (`-C instrument-coverage`) で走らせる。
2. `llvm-cov` が kome のファイルごとに、行と通った回数を書き出す。
3. `kome-lint cover` が、一度も通らなかった行を一つずつ調べる。

## 通らなくてよい行

一度も通らなかった行は、次のどちらかでなければ違反になる。

- **不変条件が破れたときの返事** (`Error::Broken` を返す行)。通らないことが正しい。通る入力があれば、
  操作のたびに `Kernel::audit` を呼ぶ決定的シミュレーションが失敗する。不変条件そのものが成り立つことは、
  台帳 (`docs/invariants.toml`) が Kani、TLA+、試験と結ぶ。
- **`docs/uncovered.tsv` に載せた行**。行ごとに、代わりに何が確かめているか (証明の名前、型の制約、
  照合する試験) を書く。

一覧は自分では増えない。載っていない行は違反で、載っているのに通るようになった行も、ファイルに無い行も
違反である (lint `lines-covered`)。

試験だけのコード (`tests.rs`、`conform.rs`、`proofs.rs` と、各ファイルの末尾の `#[cfg(test)] mod`) は数えない。

## 手元で動かす

```
rustup component add llvm-tools
scripts/ci/cover.sh
```

新しく通らない行が出たら、まずその行を通る試験を足す。到達できない分岐は、分岐そのものを無くせないかを
先に考える (例: `match` の届かない腕を、型か書き方で無くす)。それでも残る行だけを一覧に載せる。

## 限界

数えているのは行であって、分岐や値の組み合わせではない。一行に書かれた条件の片側だけを通っても、その行は
通ったことになる。値の組み合わせは、変異試験 (`cargo mutants`、週に一度)、Kani、Flux、proptest が見る。
