# 性能の測定

`cargo bench -p kome-bench` が、よく通る操作の一回あたりの時間を測る (絞り込みは `-- 名前の一部`)。
測定器は `crates/kome-bench` の中の小さなもので、依存を増やさない。1 ms 以上になる回数をまとめて
31 回測り、中央値と最小値を出す。

CI は二つのことを確かめる。

- `--smoke` で各操作を一度だけ実行し、測定の筋書きが動き続けること。
- `scripts/ci/bench-gate.sh` で、よく通る操作が遅くなっていないこと (下の「遅くなっていないことの判定」)。

## 遅くなっていないことの判定

時間そのものは機械に依存するので、合否には使えない。代わりに、同じ実行の中で「基準の仕事」
(メモリに触れない決まった量の計算、`kome_bench::reference_work`) を測り、各操作の最小値を
その最小値で割った**比**を使う。`scripts/ci/bench-gate.sh` が、この比を二通りに比べる。

| 比べる相手 | 幅 | 見つけるもの | 見つけないもの |
| --- | --- | --- | --- |
| 一つ前のコミット。同じ機械で、一つ前のコミットと今のコミットを交互に測る (`--record`、`--against`) | 1.15 倍 (`kome_bench::AGAINST_LIMIT`) | 一つのコミットが持ち込んだ 15 % を超える退行 | 15 % 以下の退行。それが何度も積み重なったもの |
| `docs/bench-gate.tsv` に記録した比 (`--gate`) | 2 倍 (`kome_bench::LIMIT`) | 積み重なって 2 倍を超えた退行。計算量が変わる退行 (実行待ちの全てを見て選ぶと、1024 本で 20 倍) | 2 倍以下の積み重なり |

- 一つ前のコミットとの比較は、機械の違いが入らないので幅を狭くできる。ただし共有の機械では、
  ほかの仕事に邪魔された測定が数十 % 遅くなる (同じコードを続けて測っても、一回ぶんの最小値が
  3 割から 7 割ずれることがあった)。邪魔は遅くする向きにしか働かないので、操作ごとに、何度か測った
  中の最小値どうしを比べる。収まるまで六回まで測り足し、六回ぶんの最小値でも幅を超えているときだけ
  失敗にする。邪魔されなかった測定どうしの比の揺れは数 % である。
- 記録との比較の幅が 2 倍なのは、CPU による比の違いを吸収するためである (メモリを多く触る操作と
  基準の仕事の速さの比は、CPU で変わる)。
- 遅くなることを受け入れるとき、または速くしたときは、同じコミットで記録を取り直す:
  `cargo bench -p kome-bench -- --baseline docs/bench-gate.tsv`。記録の比を 1.15 倍より大きく引き上げた
  操作は、そのコミットでは一つ前のコミットと比べない (測り直しの揺れで少し変わっただけの行は、比べる)。
  受け入れた変化は、記録の差分として履歴に残る。
- 記録にある操作を測っていない場合 (名前を変えた、測定を外した) は、記録との比較が失敗する。
- 参照ホストを複数の worker で動かす測定は、錠の奪い合いで数倍揺れるので、判定に入れない。
- 判定の規則そのもの (比で比べる、幅を超えたら落ちる、測っていない操作で落ちる、読めない記録で
  落ちる、二つの幅の違い) は `crates/kome-bench/src/lib.rs` の試験が確かめる。

## 参考値

Intel Xeon 2.30 GHz (仮想 4 コア) の Linux、最適化つき (`bench` プロファイル) での一回の測定。

| 操作 | 中央値 (ns) | 最小値 (ns) |
| --- | ---: | ---: |
| 実行権を借りて返す | 42.5 | 41.5 |
| 実行権を借りて返す (実行待ち 16 本) | 71.9 | 69.8 |
| 実行権を借りて返す (実行待ち 1024 本) | 147.1 | 141.0 |
| 文脈つきで一回実行する (スレッド 1 本) | 74.7 | 73.5 |
| 文脈つきで一回実行する (スレッド 64 本) | 120.2 | 118.0 |
| 文脈つきで一回実行する (スレッド 1024 本) | 158.5 | 130.8 |
| 待機を始めて通知で起こす | 58.5 | 56.9 |
| 64 バイトのメッセージを送って受け取る | 63.7 | 57.8 |
| アドレスを引く (マッピング 128 個) | 14.5 | 14.3 |
| マッピングを置いて外す (マッピング 128 個) | 168.3 | 162.7 |
| ゲストのアドレスで 4096 バイト読む (二つのマッピングをまたぐ) | 105.0 | 103.4 |
| タイマを仕掛けて期限まで進める | 22.0 | 21.1 |
| 写しを取って復元する (スレッド 64 本) | 4155.2 | 4079.5 |
| 参照ホストで一回譲る (worker 1 個、スレッド 1 本) | 68.5 | 67.2 |
| 参照ホストで一回譲る (worker 4 個、スレッド 4 本) | 1340.5 | 607.0 |
| 参照ホストで一回譲る (worker 4 個、スレッド 64 本) | 1868.9 | 1844.6 |

## 読み方

- **貸し出しは、実行待ちの数の対数で済む。** 貸せるスレッドは、貸す順序のヒープに置いてある
  (`runq.rs`)。`grant` は先頭を貸し、返ってきたスレッドを末尾の順番で入れ直す。実行待ちが
  16 本で 0.07 µs、1024 本で 0.15 µs である。全てのスレッドを見て選んでいた時は、1024 本で
  3 µs かかっていた。文脈の置き場はスレッドのスロット番号で引くので、数によらない。
- **参照ホストの値は、ゲストが何もしないときの上乗せである。** worker が一つなら錠は競合せず、
  一回の譲りに 70 ns ほどしかかからない。worker が四つあると、何もしないゲストが一つの錠を
  奪い合うので 1 から 2 µs になる。実際のゲストは一回の実行に実行量ぶんの時間を使うので、
  錠を持つ時間の割合はこれよりずっと小さい。
- 待っている者がいなければ、参照ホストは通知を呼ばない。`wait_until` で待つ者がいる間は、
  状態が変わるたびにその者を起こすので、その分だけ遅くなる。終了を待つだけなら
  `Personality::finished` を使う。
- 写しと復元は、状態の全体を複製する。大きさに比例する。
