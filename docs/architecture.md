# 責務と依存方向

kome は、複数の OS Personality に共通する状態管理だけを持つライブラリカーネルである。
この文書は、kome が何を所有し、何を所有しないか、外とどうつながるかを定める。
ここに書いた規則のうち機械で確かめられるものは `kome-lint` と CI が確かめる (各節の「検査」)。

## 依存方向

```
ゲーム用製品 → sake (実行統括・Personality・サービス・ホスト実装) → kome
```

- kome は sake を参照しない。依存クレート・機能フラグ・ビルドスクリプトを持たない。
  検査: lint `no-deps`。
- kome の通常のビルドは `no_std + alloc`。時計・ファイル・ホストのスレッドを読まない。
  検査: lint `no-std`、CI の `wasm32v1-none` と `thumbv7em-none-eabi` のビルド。
- kome は特定の OS・ホスト・実行基盤の語彙 (関数名、構造体、状態コード) を持たない。
  検査: lint `host-vocabulary`。
- 試験基盤 (`kome-testkit`)、規則の検査 (`kome-lint`)、参照ホスト (`kome-host-std`) は `std` を使う。
  kome はどれにも依存しない。

## kome が所有するもの

機構ごとに、所有するもの、満たす契約 (台帳 `docs/invariants.toml` の識別子)、置き場所を並べる。
右端の列は、同じ機構のうち kome が持たず、Personality・サービス・ホスト実装が持つものである。

| 機構 | kome が所有するもの | 契約 | 場所 | kome の外が所有するもの |
| --- | --- | --- | --- | --- |
| プロセス | 所属するスレッドと資源、アドレス空間、寿命、終了処理と回収 | PROC-1 | `process.rs` | 実行形式、モジュール、起動環境 |
| スレッド | 実行・待機・サービス中の状態、停止要求、終了要求、実行権 | RUN-1、RUN-2 | `thread.rs`、`sched.rs` | スレッド環境の ABI、例外や通知の規則 |
| メモリ | マッピング、実体への参照、範囲、権限、世代、backend への変更の通知とコードの無効化の境界 | MEM-1、MEM-2、MEM-3 | `mem.rs`、`addr.rs`、`backend.rs` | 確保 API の意味、内容のバイト列、backend の作り方、変換済みのコード |
| 資源 | 型つきの世代つき ID、参照と固定、破棄できる時点 | ID-1、OBJ-1 | `id.rs`、`object.rs` | ゲストに見せる番号と、その再利用の規則 |
| 待機 | 登録、条件の評価、結果の確定、期限との競合 | WAIT-1、WAIT-2 | `wait.rs` | 個々の同期オブジェクトの意味 |
| 時刻 | 仮想の単調時刻、期限の列、タイマ | TIME-1 | `time.rs`、`timer.rs` | 日時、時差、実時間との対応 |
| I/O | 要求の ID、進行状態、取消要求、終端の確定、公開 | IO-1 | `io.rs` | 要求の中身、出力の書式、完了の通知方式 |
| 通信路 | 容量の決まったメッセージの列とバイトの流れ、両端の保持、読める・書けるの通知、運ばれている資源の保持 | IPC-1 | `ipc.rs` | 名前、接続の手順、メッセージの書式、パイプやソケットやポートとしての意味 |
| 上限 | 表・キュー・要求数・実行量の上限、プロセスへの割り当て (`Quota`) | FX-1 | `limits.rs`、`effect.rs`、`process.rs` | 値を決める方針 |
| 失敗の区別 | 古い ID・拒否・不足・別インスタンス・内部の障害 | ERR-1 | `error.rs` | ゲストへ返す値への変換 |

プロセス間の通知・メッセージ・共有領域は次のように表す。

- **通知**: 待機可能な資源。
- **共有領域**: 実体 (backing) を複数のプロセスが保持して対応づける。
- **メッセージの列とバイトの流れ**: 通信路 (`create_channel`)。容量は作るときに決まり、送信は
  確保しない。空きが無い送信は `Sent::Full`、中身が無い受信は `Received::Empty` を返すだけで、
  スレッドを止めない。止めて待つときは、通信路が持つ「読める」「書ける」の資源を `wait` で待つ。
  この二つの数は kome が中身から決め、`signal` やタイマや I/O の通知先にはできない。
- **資源の受け渡し**: メッセージは、待機可能な資源か実体の保持を一つ運べる (`Parcel`)。送り手の
  保持は送信で通信路へ移り、受信で受け手へ移る。運ばれている間は破棄も解放もされない。受ける端の
  保持が無くなると、残っていた中身と一緒に手放す。
- **端の寿命**: 送る端と受ける端は別々に保持する。送る端が無くなると、受け手は残りを読み切った後に
  `Received::Ended` を受け取る。受ける端が無くなると、送信は `Sent::NoReceiver` になる。プロセスの
  終了は、そのプロセスが持つ端を全て外す。

決定的シミュレーションは、通信路の結果・中身・通知を、kome の型を使わない独立したモデル
(`kome-testkit` の `pipes`) と操作ごとに比べる。検査: lint `channel-model`。

## 入力と出力

- 状態は `Kernel` の値一つ。変更は `&mut Kernel` をとる操作だけが行う。操作は全て `Input` の
  変種としても表せる (`Kernel::apply`)。検査: lint `operations-covered`。
- `Effect` の取り出し (`poll_effect`、`Input::PollEffect`) も入力である。取り出すと `Effect` の席が
  空き、後の操作が受理されるかどうかが変わるので、記録・再生は取り出した位置も入力の列に持つ。
- 状態の更新に入る情報は、操作の引数、ホストからの `Completion`、`Kernel::advance` に渡す
  仮想時刻だけである。大域状態と内部可変性を持たない。検査: lint `no-globals`。
- 一度の `Kernel::advance` が処理する期限の数には目安 (`Limits::advance_batch`) がある。時刻を
  大きく進めても、一度の呼び出しの仕事は進めた長さに比例しない。目安に達したら、同じ時刻の期限を
  処理し終えたところで返り、進んだ時刻と、残りがあるか (`Advanced`) を返す。呼び出し側は残りが
  ある間、同じ時刻で呼び直す。通知をまとめたり間引いたりはしないので、どこで区切っても、起床の
  順序・結果・通知の数は同じである。検査: lint `advance-bounded`。
- 外への働きかけは `Effect` として出す。受理した操作が出しうる `Effect` の席は受理の前に
  予約し、足りなければ受理の前に `Exhausted` を返す (台帳 FX-1)。
- 同じ初期状態と同じ入力列からは、同じ返答、同じ `Effect` の列、同じ状態になる。走査は ID の
  スロット順か登録順で行う。検査: `kome-testkit` の `the_same_inputs_give_the_same_state_and_effects`。

## 単一 writer と実行権

一つの `Kernel` を更新する実行主体は一つである。ゲスト命令の実行とメモリアクセスは worker が
行い、kome はそのための実行権 (`RunPermit`) を貸す。

- 実行権は複製できず、kome の外では作れない。返すと値が消費される。検査: `sched.rs` の
  compile_fail 試験 (lint `compile-fail-kept` が数を保つ)。
- 返却を受理する前に拒否した実行権 (別の実行インスタンスのもの、古いもの) は消費せず、失敗の値
  (`NotRelinquished::Rejected`) に入れて返す。届け先を間違えても実行権は失われない。受理した後の
  内部の障害 (`NotRelinquished::Failed`) とは型で区別する。検査: lint `permit-returned`。
- 実行権は、実行インスタンス、スレッド、プロセス、worker、実行の世代、アドレス空間の世代、
  実行してよい量を持つ。kome も貸し出しを記録し、返却のときに照合する (台帳 RUN-1)。
- 実行量の単位は、ゲスト命令数のように最適化で変わらないものを実行器が選ぶ。

### 実行器の契約

実行器 (インタプリタ、JIT、ネイティブ実行) と kome の境界は `exec.rs` の `Executor` である。
実行器は、実行権を借りている間だけ実行し、区切りごとに実行量と中断の要求を確かめ、実行権が持つ
アドレス空間の世代で検証したマッピングだけを使う。止まった理由は実行権と一緒に返す。

| 実行器が止まった理由 | 実行権の返し方 | kome が確かめること | スレッドの行き先 |
| --- | --- | --- | --- |
| 貸した実行量を使い切った | `Stop::BudgetExhausted` | 実行した量が貸した量以上 | 実行待ちの末尾 |
| ゲストが実行を譲った | `Stop::Yielded` | なし | 実行待ちの末尾 |
| 中断の要求に応じた | `Stop::Interrupted` | その実行に中断を要求済み | 実行待ち (停止要求があれば貸さない) |
| API 呼び出し、停止命令、メモリ以外の例外 | `Stop::Trap` | なし | サービス中。Personality が処理して `continue_thread`、`wait`、`terminate_thread` などを呼ぶ |
| メモリアクセスの失敗 | `Stop::Fault` | なし | サービス中。Personality が配送を決める |
| ゲストがスレッドの終了まで実行した | `Stop::Exited` | なし | その終了コードで終了 |

状況と合わない理由は、状態を変えずに拒否し、実行権を返す (`NotRelinquished::Rejected`)。実行中に
受けた終了要求は、どの理由よりも先に効く。受理するかどうかと行き先は、理由・要求の有無・実行量の
全ての値について Kani が示す (`a_stop_reason_is_accepted_only_when_it_fits`)。

**文脈の保存と復元**: 止まったとき、続きの実行に要るものは全て文脈 (`Executor::Context`) にあり、
実行器の中にも worker の中にも残らない。文脈は `Contexts` が持ち、実行の間だけ取り出す。取り出した
文脈 (`Loaded`) は複製できないので、二つの worker が同じスレッドの文脈を同時に持つことは無い。
これにより、worker の数とスレッドの数は独立である。

| 実行の形 | worker | 使うもの |
| --- | --- | --- |
| スレッドごとにホストのスレッド | スレッドの数だけ | worker が自分で文脈を持ち、実行権と止まった理由を単一 writer へ送る |
| 少ない worker で多くのスレッド | `Limits::workers` | `run_once` (借りる、載せる、実行する、降ろす、返す) を worker ごとに繰り返す |
| worker が一つ | 1 | `run_once` を繰り返す |
| 順序をホストが決める (再現、探索) | 任意 | `ready_thread` で候補を数え、`grant_thread` で名指しして貸し、`run_permit` で実行する |

**貸す順序**: `grant` は、貸せるスレッドのうち優先度 (`Priority`) が最も高いものの中で、最も先に
実行待ちになったものへ貸す。kome が持つのはこの固定の順序だけである。優先度をいつ上げ下げするか、
実行中のスレッドをいつ譲らせるか (`preempt_thread`) は Personality が決める。kome は、優先度の
高いスレッドが実行待ちになっても、実行中のスレッドを自分では止めない。決定的シミュレーションは、
貸したスレッドが自分の記録 (優先度と、貸せる状態になった順) の中で最も先であることを、貸し出しの
たびに確かめる。検査: lint `executor-contract`。

貸せるスレッドは、この順序のヒープ (`runq.rs`) に置く。`grant` は先頭を貸すだけで、手数は
貸せるスレッドの数の対数で済む。各スレッドが列の中の自分の位置を持つので、名指しの貸し出し
(`grant_thread`)、停止要求、終了、優先度の変更も列を探さない。古い世代の実行が残るプロセスの
スレッドは列から外しておき、残りが無くなった時に元の順番のまま戻す (この時だけ、そのプロセスの
スレッドの数に比例する)。検査: lint `run-queue-kept`、台帳 RUN-2。

実行中のスレッドへの終了要求は、そのスレッドが実行権を返したときに確定する。

### 参照ホスト (`kome-host-std`)

一つの書き手を、実スレッドの worker でどう守るかの見本である。状態 (`Kernel`、文脈の置き場、
Personality) を一つの錠の中に置き、worker は次の順で動く。

1. 錠を取り、`grant` で実行権を借り、`start_run` で文脈を取り出す。
2. 錠を放し、ゲストを実行する。並行に進むのはここだけである。
3. 錠を取り、`finish_run` で文脈を戻して実行権を返し、Personality に続きを任せ、待っている者を起こす。

貸せるスレッドが無ければ、錠を放すのと待ち始めるのを一つの操作で行い、最も近い期限 (`next_deadline`)
が来るか、起こされるまで眠る。眠っている worker と、状態の変化を待つ者 (`wait_until`) は錠の中で数え、
状態を変えた者は、起きる理由のある相手がいるときだけ起こす (全員が実行中なら何も呼ばない)。
worker を起こす理由は、閉じた、貸せるスレッドがあるかもしれない、待つべき期限が変わった、の三つである。実行中の worker への中断 (`Effect::Interrupt`) は、実行の世代を名指しした求めとして
錠の外から読める場所に置くので、実行器は錠を取らずに止まれる。前の実行への求めが次の実行を止めることは無い。

この順序が通知を取りこぼさず、どのスレッドも決まった回数だけ実行して終了することは、Loom が
スレッドの進み方を試して確かめる (`scripts/ci/loom.sh`)。試す範囲は次のとおり。

| 筋書き | 試す進み方 |
| --- | --- |
| worker 一つ、スレッド一本 (一度譲ってから終了)、終了を待つ者 | 全て |
| worker 二つ、スレッド一本 (一度譲ってから終了)、終了を待つ者 | 自分からは止まらない場所での切り替えが 5 回まで |
| worker 二つ、スレッド二本 (すぐ終了)、終了を待つ者 | 同じく 5 回まで |
| worker 一つ、止めてあるスレッド一本を外から再開する、終了を待つ者 | 全て |

Loom が見るのは錠と通知の順序で、時刻は進めない (期限で起きる経路は実スレッドの試験が見る)。
通知を一つ抜いた変種 (`--cfg loom_broken`) が行き詰まりとして見つかることも、同じスクリプトが確かめる。
眠る者を数え忘れる、起こす理由を一つ落とす、といった誤りも、この筋書きで行き詰まりになる。
検査: lint `host-single-writer`。

## 写しと復元

`Kernel` は複製できない。同じ実行インスタンスの状態が二つあると、一つの実行権や完了通知を
両方が受け取れてしまうからである。

- `Kernel::snapshot` は写しを作る。写しは比べることと復元することだけができる。
- `Snapshot::restore` は、写しを別の実行インスタンスの状態として復元する。写しと同じ識別、
  写しの祖先 (復元元をさかのぼった実行インスタンス) の識別、実行権を貸したままの写し、応答待ちの
  I/O がある写しは拒否する。復元前の実行権と完了通知は、復元した状態では `Foreign` になる。
  取り出されていない `Effect` は復元した状態に残り、復元先のホストが取り出す。
- 実行権を貸している状態、応答待ちの I/O がある状態を復元する手順は持たない。ホストは実行権を
  全て返させ、I/O を終端させてから写しを取る。途中の状態の写しは、比べることにだけ使える。
- 型つき ID は発行元の実行インスタンスを持つ。表のスロットも、いまの資源の発行元を持つ。
  公開の操作は ID を引くときに発行元を照合し、別の `Kernel` が発行した ID を、状態を変えずに
  `Foreign` で拒否する (スロットと世代がたまたま一致しても、別の資源を操作しない)。
- 復元した状態は、写しの時点までに発行された ID をそのまま引き継ぐ (Personality の表を
  書き換えなくてよい)。復元の後に作る資源の ID は、復元先を発行元に持つ。写しの後に復元元が
  発行した ID は、復元先では資源を指さない (発行元は祖先なので `Stale`)。
- 見分けられるのは、実行インスタンスの識別が一意な場合である。同じ識別を二つの `Kernel` に
  与えないことは、実行統括 (kome の外) が守る。

検査: `tests.rs` の `a_snapshot_is_restored_only_as_another_instance_with_nothing_lent`、
`kernel.rs` の compile_fail 試験、決定的シミュレーションの復元への乗り換え、
lint `stale-at-lookup` (ID を引く一か所だけが古い ID と別インスタンスの ID を分ける)、
lint `foreign-ids-tested` (ID を受け取る全ての引数に、別インスタンスの ID を渡す試験がある)。

## 規則と検査の対応

| 規則 | 検査 |
| --- | --- |
| kome が OS・ホストへ依存しない | lint `no-deps`、`no-std`、`host-vocabulary`、OS の無いターゲットのビルド |
| 混同してはいけない値を別の型にする | 型 (`GuestAddr`、`BackingOffset`、`Id<K>`)、compile_fail 試験 |
| 状態管理へ `unsafe` が広がらない | `unsafe_code = "forbid"` (lint `required-lints`) |
| 状態の追加を既存の処理が見落とさない | lint `no-catch-all` |
| 新しい遷移の検証が抜けない | lint `ledger`、`operations-covered`、`tla-listed` |
| 走らなかった試験が合格に混ざらない | `scripts/ci/test.sh` の照合、lint `no-skipped-tests` |
| 確保しないと約束した操作が確保しない | `checks/noalloc` (`docs/memory.md`) |
| 値の範囲で決まる性質を全ての値について確かめる | Flux の篩型 (`docs/flux.md`)、lint `refinements-kept` |
| 長さに上限の無い表についての性質を証明する | Verus (`docs/verus.md`)、lint `verus-kept` |
| 実スレッドのホストが一つの書き手を守る | Loom (`scripts/ci/loom.sh`)、lint `host-single-writer` |
| その場で検査を黙らせない | lint `no-local-allow`、`escape-comments`、`ci-required` |
