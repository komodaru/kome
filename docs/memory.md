# メモリ契約

二つの契約を定める。ゲストのメモリを kome がどう管理するかと、kome 自身がホストのメモリを
いつ確保するかである。

## ゲストのメモリ

- アドレス空間は、ゲストが見る仮想アドレスの範囲と、内容を保持する実体 (backing) の対応を持つ。
  kome が持つのは範囲・対応・権限・世代で、内容のバイト列はホスト実装が持つ。
- ゲストのアドレス (`GuestAddr`)、実体の中の位置 (`BackingOffset`)、資源の ID は別の型である。
  ゲストのアドレスをホストのポインタとして扱う入口は無い。
- マッピングは、予約だけのものと実体のあるものを区別する。同じ実体を複数の範囲や複数の
  プロセスへ対応づけた別名と、独立した二つの領域は、実体の ID で区別できる。
- マッピングはページの大きさに整列し、重ならず、アドレス空間の幅に収まる (台帳 MEM-2)。
  ページの大きさとアドレスの幅はプロセスごとに決め、ホストの確保の粒度とは別である。
- `Kernel::translate` が基準の経路である。範囲外、権限違反、予約だけの部分、マッピングの境界を
  またぐアクセスを、発生位置つきの結果 (`MemFault`) として返す。高速経路は、この経路と同じ
  結果になることを比べて確かめる。

### backend との境界

内容のバイト列を持つ側 (backend) の作り方は kome の外で決める。ゲストのアドレスをそのままホストの
連続領域に置く作り方、アクセスごとにマッピングを引く作り方、書かれたページだけを持つ作り方の
どれでも、境界 (`backend.rs`) は同じである。

| 約束 | kome が用意するもの | 検査 |
| --- | --- | --- |
| 内容は、実体の ID と実体の中の位置で読み書きする | `Contents` | 型 (ゲストのアドレスを渡す引数が無い) |
| ゲストのアドレスでのアクセスの基準は、`translate` で引いた結果である | `guest_read`、`guest_write` | 決定的シミュレーションが、結果と失敗の位置をモデルと比べる |
| アドレス空間の変更は、受理した直後に、一度だけ知らせる | `SpaceObserver`、`map_observed`、`unmap_observed`、`protect_observed` | 通知だけから組み立てたアドレス空間 (`kome-testkit` の `shadow`) がモデルと一致する |
| 変換済みのコードは、外した範囲と権限を変えた範囲で捨てる | `CodeCache`、`CodeWatch`、`MapChange::invalidates_code` | 試験 `every_accepted_space_change_is_told_once_and_drops_the_code_it_must` |
| 書き込みは、書いた実体を実行できる権限で見せている全ての場所のコードを捨てさせる。書き込み先とは別の範囲、別のプロセスが同じ実体を見せている場合 (別名) も含む | `guest_write_watched`、`Kernel::executable_views` | 決定的シミュレーションが、捨てさせた範囲をモデルのページから引いたものと操作のたびに比べる。試験 `a_write_through_another_view_drops_the_code_of_every_executable_view` |
| backend が書き込みの途中で失敗しても、範囲の全体についてコードを捨てさせてから失敗を返す (内容は一部変わっているかもしれない)。何も書かずに失敗したとき (範囲のどこかが書けない) は捨てない | `guest_write_watched` | 決定的シミュレーション (途中のバイトで失敗する backend)。試験 `a_write_that_fails_partway_still_drops_the_code_it_may_have_changed` |

速い経路 (アドレスを直接使う、引いた結果を覚えておく) は、通知を受けて自分の表を直し、基準の経路と
同じ結果を返す。実行器が自分の速い経路でゲストのメモリへ書くときは、実行器がコードを捨てる
(書き込み先に実行の権限が無くても、同じ実体を別の場所からコードとして見せていることがある。
`Kernel::executable_views` で引ける)。`executable_views` は全てのプロセスのマッピングを見るので、
手数はマッピングの総数に比例する。
通知を受けても、実体の内容は `Effect::BackingReclaimed` が出るまで手放さない (台帳 MEM-1)。
検査: lint `backend-boundary`。

### 権限の変更と実体の寿命

権限を減らす変更 (実体のあるマッピングを外す、権限を狭める) では、二つの条件を別々に守る。

1. **変更後の権限を守る (台帳 MEM-3)**: 変更の時点で実行中だったそのプロセスのスレッドへ中断を
   要求し、それらが実行権を返し終えるまで、そのプロセスのどのスレッドにも実行権を貸さない。
   実行器は実行権が持つアドレス空間の世代で検証したマッピングだけを使う。
2. **使用中の実体を解放しない (台帳 MEM-1)**: 外したマッピングの実体への参照は、古い世代の
   実行が残る間は保留として持ち続ける。`Effect::BackingReclaimed` を出すのは、保持・
   マッピング・保留が全て無くなったときである。

保留は、一つのアドレス空間につき一つの実体を一度だけ持つ。古い世代の実行が残る間に同じ実体を
何度外しても記録は増えず、保留の数は生きている実体の数を超えない (`Kernel::audit` が重複を検出する)。

権限の変更 (`protect`) は次のように扱う。

- 範囲の全体が既に同じ権限なら、何も変えない。世代も進めず、分割も中断の要求もしない。
- 変更の後、隣り合う項目が同じ権限で同じ実体の続きを見せていれば、一つの項目にまとめる。
  権限を変えて戻す操作を繰り返しても、項目の数は見え方の違いの数を超えない。上限の判定は、
  まとめた後の数で行う。
- 実行中のスレッドを止める (上の 1) のは、できなくなるアクセスがある変更だけである。権限を
  増やすだけの変更は世代を進めるが、実行を止めない。古い世代で検証したマッピングは変更の前の
  狭い権限しか持たないので、変更後の権限を超えるアクセスは起きない。

## kome 自身の確保

### 上限

kome の表は全て `Limits` で上限を持つ。上限に達した操作は、状態を変えずに
`Exhausted(資源の種類)` を返す。

一つのプロセスが使える量は、プロセスへの割り当て (`Quota`) でさらに絞れる:
スレッドの数、I/O 要求の数、参照できる資源の種類数、マッピング数、実体つきで対応づけている
バイト数。効くのは `Limits` と割り当ての小さい方である。割り当てを今の使用量より小さくしても、
既にあるものは取り上げず、増やす操作だけを拒否する。値を決めるのは kome の外である。
プロセスごとの上限を見る箇所が割り当てを通ることは、lint `process-quota` が確かめる。

### 確保の失敗

確保は、失敗を返せる経路 (`store.rs` の `List`・`Queue` の `try_reserve`) だけを通る。
ホストのメモリが足りなければ、状態を変えずに `Exhausted(HostMemory)` を返す。
`Vec` などを直接使うこと、確保に失敗すると止まるマクロを使うことは lint `raw-collections` が拒否する。

回復できる範囲は次のとおり。確保に失敗した操作は受理されておらず、呼び出し側は資源を解放して
から同じ操作をやり直せる。確保を伴わない操作 (下の表) は、メモリが足りない状況でも必ず進む。
したがって、メモリ不足の中でも、実行権の返却、待機の解除、I/O の終端、スレッドとプロセスの
終了、資源の回収は止まらない。

### 確保する操作と、確保しない操作

確保は、初期化と資源を作る操作にまとめる。作る操作は、その資源が後で必要とする容量
(起床のための実行待ち行列の席、通知のための `Effect` の席、期限の列の席、保留の席) も
その場で確保する。

| 確保しうる操作 | 確保するもの |
| --- | --- |
| `Kernel::new` | `Effect` のキュー (上限ぶん)、実行権の表 (worker の上限ぶん) |
| `create_process`、`create_thread`、`create_object`、`create_backing`、`create_timer`、`prepare_io` | 表のスロット、所属の列、実行待ち行列の席 |
| `create_channel` | 表のスロット、通信路の容量ぶんの記憶域 (バイト列と、メッセージごとの長さの列)、プロセスの参照の列 |
| `retain_object`、`retain_backing`、`retain_channel` | プロセスの参照の列 |
| `receive` | 資源を運ぶメッセージを受け取るときの、受け手の参照の列 |
| `map`、`unmap`、`protect` | マッピングの列 (範囲の途中を変えると項目が増える)、保留の列 |
| `wait` | 待機の対象の列、対象ごとの待機者の列、期限の列 |
| `arm_timer` | 期限の列 |
| `snapshot`、`Snapshot::restore` | 状態全体の写し (確保済みの容量も写す) |

確保しない操作が使う容量を、どの操作が確保し、どの操作が使うかは `docs/capacity.tsv` にある。
`Kernel::audit` はその容量が残っていることも確かめる (写しから復元した状態でも同じ)。
容量の中でだけ追加する呼び出しが表に無ければ、lint `capacity-audited` が拒否する。

次の操作は確保しない。

| 確保しない操作 | 分類 |
| --- | --- |
| `grant`、`grant_thread`、`relinquish`、`preempt_thread`、`set_priority` | 実行権の貸し出しと返却、優先度、譲らせる要求 (スケジューリング) |
| `set_quota` | プロセスへの割り当ての変更 |
| `continue_thread`、`suspend_thread`、`unsuspend_thread` | スレッドの再開と停止 |
| `signal`、`interrupt_wait`、`advance` | 起床 (通知、割り込み、期限) |
| `issue_io`、`cancel_io`、`complete`、`publish_io` | I/O の進行と終端 |
| `release_object`、`release_backing`、`release_io`、`release_channel`、`disarm_timer`、`drop_timer` | 解放 |
| `send` | 送信 (中身は、作るときに確保した容量へ入れる) |
| `terminate_thread`、`exit_process` | 終了と回収 |
| `poll_effect` | `Effect` の取り出し |

検査: `checks/noalloc` が大域のアロケータで確保を数え、決定的シミュレーションが上の操作を
呼ぶ間の確保が 0 であることを確かめる。決定的シミュレーションが上の操作を必ず印つきで呼ぶこと、
この表と検査の一覧が一致することは lint `quiet-operations` が確かめる。
